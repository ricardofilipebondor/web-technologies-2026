1. Introducere

eSC gestionează operațiunile unui club de șah: membri, antrenori, săli, activități, competiții, premii, deplasări.

  • Frontend — HTML, CSS responsive, JavaScript vanilla, fetch asincron;
  • Backend — API REST stateless (JWT), PHP fără framework, backend/server.php;
  • Bază de date — SQLite via PDO, modele în database/models/.

Datele se încarcă exclusiv prin API JSON; nu există server-side rendering.

2. Scop și domeniu

Digitalizarea proceselor administrative și sportive ale clubului, cu acces pe roluri și import/export în formate deschise (CSV, JSON, XML).

Constrângeri: fără framework-uri Web; HTML și CSS valide; comunicare Ajax; cod sub licență MIT.

3. Roluri și permisiuni

Definite în backend/config/app.php ($ROLE_PERMISSIONS, $MENU_ITEMS). Verificare API: AuthMiddleware::requireModule() după validare JWT. Meniu UI: GET /menu (filtrat pe rol).

RolModule accesibile
administrator dashboard, members, coaches, teams, groups, halls, activities, competitions, participations, rankings, prizes, trips, expenses, reimbursements, admin
antrenor dashboard, members, coaches, teams, groups, halls, activities, competitions, participations, rankings, prizes
responsabil_financiar dashboard, trips, expenses, reimbursements

La înregistrare (POST /users) se pot alege doar rolurile antrenor și responsabil_financiar. Rolul administrator se atribuie din modulul admin (GET /users, PUT /users/{id}).

4. Cerințe funcționale

4.1 Antrenori

  • CRUD — /coaches
  • Câmpuri: nume, email, telefon, specializare, disponibilitate, rol
  • Legătură cu grupe și activități

4.2 Membri

  • CRUD — /members; categorii: junior, senior, amator, profesionist
  • Profil cu participări și premii — getMemberProfile() în backend/helpers.php
  • Import POST /members/imports; export GET /members?format=csv|json|xml

4.3 Săli și activități

  • Săli cu capacitate, dotări, intervale orare — /halls, POST /halls/{id}/slots
  • Activități: antrenament, curs, workshop, simultan — /activities
  • Verificare conflicte sală/antrenor — Activity::hasHallConflict(), hasCoachConflict()

4.4 Competiții

  • CRUD competiții — /competitions
  • Participări, punctaj, loc — /participations
  • Clasamente — /rankings; export ?format=csv|json|xml

4.5 Echipe și premii

  • Echipe, componență (POST /teams/{id}/members), rezultate — /teams
  • Grupe — /groups
  • Premii — /prizes

4.6 Deplasări și finanțe

  • Deplasări, membri participanți — /trips
  • Cheltuieli — /expenses
  • Deconturi (agregare trips + expenses) — /reimbursements; export CSV, JSON, PDF

4.7 Administrare

  • Gestionare utilizatori — GET /users, POST /users; roluri — GET /roles, PUT /users/{id}

7. Model de date

18 tabele SQLite: roles, users, coaches, members, groups, group_members, halls, hall_slots, activities, teams, team_members, team_results, competitions, participations, prizes, trips, trip_members, expenses.

Proveniența datelor:

  • Date demo în database/schema/database.sql (via install.php);
  • Introducere manuală prin formulare CRUD;
  • Import CSV/JSON/XML (membri);
  • Fără API extern — date locale în SQLite.

Diagrame ER: ARCHITECTURE.md (secțiunile 8–12).

8. Interacțiune utilizator

  1. Autentificare pe frontend/index.html (POST /sessions → JWT);
  2. După login → app.html;
  3. Meniu lateral din GET /menu;
  4. Navigare hash (#/members etc.) fără reîncărcare — router.js → window.pages[module];
  5. Modulele încarcă date via API și afișează tabele/formulare;
  6. CRUD prin POST/PUT/DELETE; răspunsuri REST (201 Created, 204 No Content).

Design UI: DESIGN.md.
