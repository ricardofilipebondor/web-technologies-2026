Abstract

Acest document reprezintă specificarea cerințelor sistemului (SRS) conform standardului IEEE pentru aplicația Web eSC (Chess Club Manager). Aplicația servește ca platformă centralizată pentru digitalizarea proceselor administrative, sportive și financiare din cadrul unui club de șah, oferind arhitectură API RESTful stateless pe backend (PHP) și un Single-Page Application pe frontend (Vanilla JS).

1. Introducere

1.1 Scopul documentului

Scopul acestui document este de a descrie în detaliu cerințele funcționale și non-funcționale ale sistemului eSC. Documentul este destinat echipei de dezvoltare, profesorilor evaluatori și administratorilor viitori ai sistemului pentru a asigura o înțelegere comună a capabilităților platformei.

1.2 Domeniul de aplicare

Sistemul eSC va gestiona operațiunile interne ale clubului: evidența membrilor, organizarea antrenamentelor, rezervarea sălilor, participarea la competiții și decontarea cheltuielilor de deplasare. Sistemul elimină procesele bazate pe hârtie, automatizează verificarea conflictelor logistice și oferă exporturi de date în formate deschise (CSV, JSON, XML, PDF).

2. Descriere Generală

2.1 Perspectiva produsului

eSC este un sistem de tip monolit modular, self-contained, fără framework-uri externe. Frontend-ul interacționează asincron via AJAX cu un server backend PHP, care persistă datele într-o bază de date relațională SQLite locală. Sistemul este complet decuplat, comunicarea realizându-se exclusiv prin JSON.

2.2 Clase de utilizatori și permisiuni

  • Administrator: Acces complet la toate cele 15 module, inclusiv managementul utilizatorilor și al rolurilor.
  • Antrenor: Acces la gestionarea membrilor, echipelor, grupelor, competițiilor și rezervarea intervalelor orare în săli.
  • Responsabil Financiar: Acces restricționat strict la modulele de deplasări, cheltuieli și deconturi.

3. Funcționalități ale Sistemului

3.1 Gestionarea Entităților Umane

Sistemul permite operațiuni CRUD pentru antrenori și membri. Membrii sunt clasificați în funcție de nivel. Se permite importul în masă prin fișiere și exportul datelor. Profilul unui membru expune automat istoricul competițional agregat și premiile obținute.

3.2 Gestionarea Logistică

Alocarea resurselor spațiale pentru antrenamente, cursuri și workshop-uri. Sistemul previne automat suprapunerile validând disponibilitatea sălii și a antrenorului pentru un interval orar specificat direct la nivel de model de date.

3.3 Competiții și Echipe

Formarea echipelor și gestionarea participărilor la competiții externe sau interne. Funcționalitatea include generarea automată a clasamentelor și alocarea premiilor către membrii sau echipele participante, cu posibilitatea extragerii de rapoarte de performanță.

3.4 Deplasări și Deconturi

Modul destinat responsabilului financiar pentru planificarea deplasărilor și agregarea costurilor logistice (transport, cazare). Costurile sunt asociate participărilor, generând deconturi oficiale exportabile în format PDF.

4. Cerințe Non-Funcționale și Tehnice

4.1 Securitate și Autentificare

  • Autentificare Stateless (JWT): Identificarea utilizatorilor se realizează prin JSON Web Tokens (algoritm HS256). Token-ul este stocat pe client în localStorage și este atașat fiecărei cereri HTTP în header-ul Authorization: Bearer.
  • Autorizare: Middleware-uri backend (RBAC) interceptează cererile, decodifică JWT-ul, verifică integritatea semnăturii și validează accesul pe baza rolului conținut în payload.
  • Protecție date: Utilizarea de PDO Prepared Statements previne atacurile SQL Injection. Protecția XSS este asigurată pe client prin funcții de evadare a caracterelor (escapeHtml) la injectarea datelor în DOM.

4.2 Arhitectură și Calitate Software

  • Arhitectură Client: Single-Page Application (SPA) folosind Vanilla JavaScript, navigare asincronă pe bază de Hash Routing.
  • Arhitectură Server: API REST pur, respectând constrângerile de uniform interface, oferind răspunsuri JSON, utilizând corect metodele HTTP (GET, POST, PUT, DELETE) și implementând coduri standard pentru erori (RFC 7807).
  • UI/UX: Interfață responsivă, scalabilă pe dispozitive mobile, bazată pe tehnici moderne CSS (Flexbox/Grid).

5. Modelul Datelor

Persistența este asigurată de SQLite. Schema conține 18 tabele relaționale normalizate. Intersecțiile de tip Many-to-Many specifice domeniului sportiv sunt rezolvate prin tabele de joncțiune (team_members, group_members, trip_members). Baza de date nu se bazează pe API-uri externe pentru stocarea resurselor esențiale.
